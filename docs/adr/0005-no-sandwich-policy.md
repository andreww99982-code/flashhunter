# ADR 0005: Сэндвич-атаки вне области проекта (этическая политика)

**Дата:** 2026-09-25 · **Статус:** принято (ограничение продукта)

## Контекст

Технически сэндвич (buy-before / sell-after относительно пользовательского свопа)
использует те же примитивы, что и законный бэкран: знание содержимого мемпула,
быстрый расчёт и отправка bundle. Соблазн добавить его как «ещё одну стратегию»
велик: маржинальность высокая, входной барьер низкий.

## Решение

Сэндвич-стратегия **не реализуется** и не будет реализована. Это не
консервативный дефолт, а жёсткое ограничение продукта:

* стратегия `backrun` работает только по **собственной** сделке пользователя
  (backrun = исполнение после свопа в том же блоке, без движения цены против него);
* параметр `sandwich` в конфигурации `backrun` зафиксирован как `False`, и
  попытка его включить валится валидацией;
* контракт `JITVault` умеет только предоставлять ликвидность (mint/collect),
  у него нет пути «купить до свопа и продать после»;
* в `docs/` и README зафиксирована политика: эксплойты, атаки на другие боты,
  KYC/AML-обходы и обфускация — вне области проекта.

## Последствия

**Плюсы:** проект не причиняет прямого вреда пользователям DEX; меньше
регуляторного и репутационного риска; проще аудит кода (нет злонамеренной логики).

**Минусы:** отказ от одного из самых доходных источников MEV; конкуренты,
использующие сэндвич, иногда зарабатывают больше на том же потоке. Это принято
сознательно: цель проекта — устойчивый бизнес, а не максимум в отдельном блоке.
