# Rust: горячий путь FlashHunter

Восемь крейтов рабочего пространства (edition 2021, toolchain зафиксирован в
`rust-toolchain.toml`). Здесь живёт всё, что измеряется микросекундами:
разбор блока, индекс пулов, поиск циклов, симуляция, сборка и отправка bundle.

```
rust/
├── Cargo.toml            # воркспейс: 8 членов + единые версии зависимостей
├── rust-toolchain.toml   # канал 1.90 + rustfmt + clippy (одинаково у всех и в CI)
└── crates/
    ├── shared/           # адреса, chain id, конфигурация из ENV, gwei-хелперы
    ├── chain-access/     # провайдеры RPC: состояние чейна, голова, комиссии, пул с ротацией
    ├── ingestor/         # подписка на блоки, публикация событий (бинарник fh-ingestor)
    ├── pool-indexer/     # индекс пулов: применение Swap/Sync, свежесть, выход по V2-формуле
    ├── graph-engine/     # граф токенов: поиск циклов ≤ 4 хопов, отсечение по комиссиям
    ├── sim-engine/       # локальная симуляция (revm): маршрут, газ, чистая прибыль
    ├── bundle-builder/   # сборка bundle: calldata, nonce, maxFee, replacement, cancel
    └── relay-client/     # fan-out по 8 релеям, статистика приёма и задержек
```

## Сборка и проверки

```bash
cd rust
cargo build --release --workspace     # сборка всех бинарников
cargo test --workspace                # юнит-тесты всех крейтов
cargo fmt --all -- --check            # форматирование
cargo clippy --all-targets -- -D warnings   # предупреждения = ошибки
```

Через корневой Makefile:

```bash
make rust-check    # fmt + clippy
make rust-test     # cargo test по воркспейсу
```

## Бюджеты латентности

Крейты спроектированы под бюджеты ТЗ §1.2 (см. `python/flashhunter/api/ws.py`):

| Крейт | Бюджет | Ключевые решения по производительности |
|-------|--------|----------------------------------------|
| `chain-access` | — | Пул провайдеров с ротацией: упавший RPC не останавливает поток блоков |
| `ingestor` | 5000 мкс | Заголовок блока обрабатывается без аллокаций в горячем цикле |
| `pool-indexer` | 2000 мкс | Снимок пула — структура фиксированного размера; `is_stale` без обращений к таймеру системы |
| `graph-engine` | 3000 мкс | Рёбра кэшируются в `Vec`, обход ограничен 4 хопами, отсечение по произведению комиссий |
| `sim-engine` | 8000 мкс | Проверки (газ, комиссия флеша, минимальная прибыль) до дорогого расчёта |
| `bundle-builder` | 3000 мкс | Nonce-менеджер в памяти; сериализация в RPC-формат одной структурой |
| `relay-client` | 10000 мкс | Fan-out по всем релеям сети; таймаут 250 мс на релей, статистика по каждому |

## Связь с Python-контуром управления

Контракты обмена — `proto/flashhunter.proto`. В локальном (`FLASHHUNTER_ENV=dev`)
режиме сервисы заменяются моками внутри Python-процесса, поэтому `docker compose up -d`
не требует сборки Rust. Прод-образ собирается из `infra/docker/Dockerfile.rust`.

## Что здесь сознательно НЕ делается

Сэндвич-логики в бэкран-крейтах нет и не будет: политика проекта описана в
`docs/adr/0005-no-sandwich-policy.md`, CI-задача `ethics-check` следит за этим.
