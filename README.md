## 1. Что это

FlashHunter — самодостаточная система из трёх частей:

| Часть | Что делает | Технологии |
|-------|-----------|-----------|
| **Горячий путь** | От нового блока до отправки bundle в релеи за единицы миллисекунд | Rust 1.82 (edition 2021), alloy, revm |
| **Контур управления** | Риск, PnL, аудит, API, панель, бэктест, уведомления | Python 3.12, FastAPI, SQLAlchemy |
| **Исполнение** | Атомарные сделки с флеш-кредитом и защитой средств | Solidity 0.8.24, Foundry, Echidna |

**Ключевая идея:** бот ищет расхождения цен между пулами и ликвидационные возможности,
проверяет их локальной симуляцией и исполняет атомарно через flash-loan. Если после
свопов прибыль меньше заявленного минимума — транзакция ревертится целиком, потери
ограничены сожжённым газом.

**Что вы получите из коробки:** рабочий стек, поднимающийся одной командой, панель
на 12 страниц с Material Design 3 + Liquid Glass, мок-рынок для безопасной отладки,
130 Python-тестов, Foundry-тесты с фаззингом, Echidna-инварианты, схемы для SQLite,
Postgres и ClickHouse, конфигурацию для Docker, Kubernetes, Terraform и Ansible.

## 2. Быстрый старт

### Вариант А: одна команда (Docker)

```bash
git clone https://github.com/flashhunter/flashhunter.git
cd flashhunter
docker compose up -d
```

Через 2–4 минуты (первая сборка ставит зависимости) откройте **http://localhost:8000**.
Логин `admin`, пароль `admin` — система сразу потребует сменить пароль.

### Вариант Б: с автогенерацией секретов

```bash
bash scripts/bootstrap.sh
```

Скрипт проверит Docker, создаст `.env` со случайными `JWT_SECRET` и паролями,
соберёт стек, дождётся health-check и напечатает учётные данные.

### Вариант В: локальная разработка без Docker

```bash
make install      # pip install -e "python[dev]" + npm install
make dev          # API на :8000 (SQLite, мок-рынок)
# или оба сервера сразу (API + Vite dev с проксированием /api и /ws):
bash scripts/dev.sh
```

### Профили инфраструктуры

```bash
docker compose --profile cluster up -d                    # + Postgres, ClickHouse, Redis
docker compose --profile cluster --profile observability up -d  # + Prometheus, Grafana
docker compose --profile edge up -d                       # + nginx (gzip, rate-limit, TLS)
```

### Что происходит после старта

* Бот работает в режиме **DRY-RUN** (`FLASHHUNTER_DRY_RUN=true`) с **мок-рынком**
  (`MOCK_MARKET_DATA=true`): находит возможности, симулирует сделки, пишет статистику,
  но **не отправляет ничего в сеть** и не требует RPC-ключей.
* Панель показывает живые данные: возможности появляются каждые несколько секунд.
* Чтобы увидеть бота в деле, загляните на `/dashboard`, `/opportunities` и `/backtest`.

Полное описание — [`docs/architecture.md`](docs/architecture.md);
причины ключевых решений — [`docs/adr/`](docs/adr/README.md).

**Разделение труда.** Rust отвечает за то, что измеряется микросекундами (разбор блока,
индекс пулов, поиск циклов, симуляция, сборка и отправка bundle). Python отвечает за то,
что важно менять быстро и читать человеком (риск-лимиты, панель, аудит, бэктест).
Связь слоёв описана в [`proto/flashhunter.proto`](proto/flashhunter.proto).

**Режимы работы.** По умолчанию всё живёт в одном Python-процессе (легко запускать,
легко отлаживать). Кластерный режим поднимает Rust-сервисы
(`infra/docker/Dockerfile.rust`) и прод-хранилища.

## 4. Стратегии

Семь стратегий, все — «честный MEV»: мы не двигаем цену против пользователя.

| Стратегия | Суть | Сети (по умолчанию) | Ключевые параметры |
|-----------|------|---------------------|--------------------|
| `dex_arb` | Расхождение цены между двумя пулами: купить дешевле, продать дороже | 1, 8453, 42161, 10, 137 | мин. прибыль $12, размер $500–250k, ROI ≥ 0.05%, газ 340k |
| `triangular` | Цикл из трёх токенов внутри одного DEX и между DEX | 1, 8453, 42161 | мин. прибыль $10, размер $800–150k, газ 420k |
| `stable_peg` | Депег стейблкоинов (USDC/USDT/DAI) | 1, 137, 42161 | отклонение 1–50 bps, $8, $2k–400k, газ 260k |
| `liquidation` | Ликвидация позиций Aave V3 с бонусом 5–10% | 1, 8453, 42161, 10 | HF < 1.02, прибыль $40, закрытие 50% долга |
| `jit` | JIT-ликвидность под крупный своп в Uniswap V3 | 1, 8453 | своп ≥ $50k, прибыль $5, капитал $750k, диапазон 0.5% |
| `backrun` | Арбитраж последствий крупного свопа в том же блоке | 1, 8453 | своп ≥ $25k, импакт 3–60 bps, прибыль $10, **sandwich = false** |
| `intent` | Исполнение кросс-чейн интентов за комиссию | 1, 8453, 42161 | комиссия ≤ 25 bps, ETA ≤ 900 с, прибыль $25 |

Каждую стратегию можно включать/выключать и настраивать со страницы `/strategies`.
Флаг `sandwich` в `backrun` зафиксирован в `false` и защищён валидацией — см.
[`docs/adr/0005-no-sandwich-policy.md`](docs/adr/0005-no-sandwich-policy.md).

## 6. Горячий путь и бюджеты латентности

Полный цикл от блока до bundle укладывается в **~5 мс**; каждый сервис имеет свой бюджет,
который проверяется метрикой `within_budget`:

| Сервис | Бюджет | Что делает |
|--------|--------|-----------|
| `ingestor` | 5000 мкс | Разбор заголовка блока, дельта сети |
| `pool-indexer` | 2000 мкс | Применение событий пулов к снимку |
| `graph-engine` | 3000 мкс | Поиск циклов ≤ 4 хопов, отсечение по комиссиям |
| `strategies` | 5000 мкс | Отбор кандидатов (intent — 20000 мкс) |
| `sim-engine` | 8000 мкс | Локальная симуляция маршрута (revm) |
| `risk-engine` | 1000 мкс | Лимиты, экспозиция, свежесть данных |
| `bundle-builder` | 3000 мкс | Calldata, nonce, maxFeePerGas |
| `relay-client` | 10000 мкс | Fan-out по релеям, таймаут 250 мс на релей |
| `api` | 20000 мкс | Отдача данных панели |

Если бюджет нарушается, страница `/latency` подсвечивает сервис, а Prometheus поднимает
алерт `LatencyBudgetExceeded`: даже прибыльные сделки не помогут, если конкурент
успевает отправить bundle раньше.

## 7. Управление риском

Риск-движок имеет **право вето** на любую сделку и работает независимо от стратегий
([ADR 0004](docs/adr/0004-risk-engine-veto.md)).

| Лимит | По умолчанию | Поведение при нарушении |
|-------|--------------|-------------------------|
| Дневной убыток | $500 | Отказ в новых сделках + kill-switch |
| Часовой убыток | $150 | Пауза 30 минут + уведомление |
| Доля ревертов | 35% | Отключение стратегии до разбора |
| Экспозиция на сеть | $50 000 | Отказ в сделке |
| Экспозиция на токен | $20 000 | Отказ в сделке |
| Потеря соединения | 5 с | Отмена неотправленных bundle |
| Устаревшие данные пула | 5 с | Запрет сделок по этому пулу |

**Kill-switch** — аварийный тормоз. Взводится автоматически (при нарушении лимитов)
или кнопкой оператора на `/settings`; снять его можно только осознанным действием
человека. Каждое решение риск-движка попадает в аудит.

## 8. Контракты

Четыре контракта Solidity 0.8.24 в [`contracts/`](contracts/README.md):

| Контракт | Роль |
|----------|------|
| `FlashLoanArbitrage` | Флеш-кредит Aave V3 → свопы → проверка прибыли → возврат долга, всё в одной транзакции |
| `Liquidator` | Ликвидация позиций Aave V3 с флеш-кредитом на погашение долга |
| `JITVault` | JIT-ликвидность: `mint` → целевой своп → `burn` → `collect` атомарно |
| `BridgeAdapter` | Кросс-чейн интенты: блокировка средств, исполнение солвером, комиссия ≤ 25 bps |

**Гарантии:**

1. **Атомарность.** Прибыль меньше `minProfit` — транзакция ревертится целиком.
2. **Роли.** Деньги двигает только `keeper`; роли и снятие прибыли — только `owner`.
3. **Пауза.** `setPaused(true)` останавливает всё мгновенно (используется kill-switch).
4. **Ограничение комиссии интентов.** `MAX_FEE_BPS = 25` зашито в контракт.

Тесты: `forge test` (unit + fuzz, 512 ранов в CI) и `make contracts-invariants`
(Echidna: 5 инвариантов, включая «баланс Aave никогда не уменьшается»).

```bash
cd contracts
forge install foundry-rs/forge-std    # один раз
forge test -vv                        # тесты
make contracts-invariants             # инварианты
forge script script/Deploy.s.sol:Deploy --rpc-url $ETH_RPC_URL --broadcast --verify
```

## 12. Бэктест

```bash
make backtest                      # 500 блоков, профиль volatile, отчёты в data/reports/
bash scripts/backtest.sh 200 42 calm   # блоков=200, seed=42, профиль=calm
```

Профили рынка: `calm`, `normal`, `volatile`, `stress`. Движок
(`flashhunter.backtest.engine`) умеет:

* прогонять мок-рынок на N блоков (`run_mock`) или воспроизводить исторические снимки (`run_replay`);
* считать метрики: equity-кривую, максимальную просадку, волатильность, Sharpe, конверсию по стратегиям;
* подбирать параметры (`grid_search`) и возвращать лучшие комбинации;
* экспортировать отчёт в JSON и CSV.

Пример результата (профиль volatile, 60 блоков, seed 11): 1324 найденные возможности,
итоговый net $811 291, Sharpe 17.4, доминируют `liquidation` и `dex_arb`.
Страница `/backtest` даёт то же самое из панели, плюс графики.

## 16. Безопасность

* **Авторизация.** JWT + сессии с ревокацией; при первом входе обязательна смена пароля;
  поддержана 2FA (TOTP, QR-код в панели).
* **Секреты.** API-ключи и приватные ключи кошельков шифруются, в UI маскируются
  (`supe••••1234`). В логах и метриках секреты не появляются.
* **Ключи кошельков.** Никогда не в git: в проде — KMS/HSM + инжект при деплое с правами
  `0400` и аудитом доступа ([ADR 0006](docs/adr/0006-keys-in-kms.md)). Preflight-скрипт и CI
  блокируют попадание ключа в репозиторий.
* **Ограничение ущерба.** Горячий кошелёк держит только дневной запас; прибыль автоматически
  уходит на холодный адрес; баланс keeper-а ограничен по экспозиции.
* **Контейнеры.** Непривилегированный пользователь, `readOnlyRootFilesystem`,
  отброшенные capabilities, IMDSv2 обязателен, в k8s — `NetworkPolicy` и
  `pod-security-standard: restricted`.
* **Проверки в CI.** CodeQL, `pip-audit`, `npm audit`, `cargo audit`, Trivy, gitleaks,
  плюс проверка «ключ не попал в репозиторий» и «в код не прокралась запрещённая
  политикой логика».

## 17. Регламент обкатки перед боем

Переход в боевой режим — только по чек-листу (ТЗ §16). Помощник — `make preflight`:

| Шаг | Что делаем | Критерий перехода |
|-----|-----------|-------------------|
| 1 | Запуск в `dry_run=true` с реальными RPC | API отвечает, `blocks_processed` растёт |
| 2 | **24 часа** наблюдения | Kill-switch не срабатывал ложно, алертов нет |
| 3 | `make backtest` и страницы `/analytics`, `/latency` | Бэктест прибыльный, латентность в бюджете |
| 4 | `make preflight` | Блокирующих проблем нет |
| 5 | `FLASHHUNTER_DRY_RUN=false`, малый баланс keeper-а | Первая реальная сделка видна в `/history` |
| 6 | Увеличение банка | После недели без инцидентов |

```bash
make preflight   # проверит ключи, лимиты, часы, uptime, отчёты бэктеста и запретит переход при рисках
```

## 18. Этическая политика

Проект реализует и будет реализовывать **только легальный MEV**:

✅ арбитраж между пулами, ликвидации, JIT-ликвидность, бэкран собственных сделок,
исполнение пользовательских интентов по честной цене.

❌ **сэндвич-атаки** на пользовательские свопы, эксплойты и взломы, атаки на других ботов,
обход KYC/AML, обфускация кода и сокрытие потока средств.

Сэндвич исключён не «по умолчанию», а конструктивно: флаг `sandwich` в стратегии `backrun`
зафиксирован в `false`, контракт `JITVault` не умеет покупать до свопа и продавать после,
в CI работает job `ethics-check`, который падает при появлении такой логики.
Подробнее — [`docs/adr/0005-no-sandwich-policy.md`](docs/adr/0005-no-sandwich-policy.md).

## 20. Решение проблем

| Симптом | Причина | Что делать |
|---------|---------|-----------|
| `docker compose up` падает на сборке | Нет доступа к реестру/сети | Повторите; проверьте `docker compose build api --no-cache` |
| Панель открывается, но данные пустые | БД только создана, оркестратор не успел | Подождите 10–20 секунд; проверьте `curl localhost:8000/api/v1/health` |
| `401` после логина | Истёк JWT или панель открыта в другой вкладке | Перезайдите; сессии видны на `/settings` |
| Требует сменить пароль | Работает защита первого входа | Смените пароль (это требование ТЗ, а не дефект) |
| `/opportunities` пуст | Тихий рынок или выключены стратегии | Проверьте `/strategies`; прогоните `/backtest` |
| Латентность «в красном» | Медленный CPU/RPC или мало ресурсов | Проверьте `docker stats`, смените RPC, снизьте число сетей |
| Kill-switch взведён | Сработал лимит убытка или нажал оператор | Разберитесь в причине на `/logs`, затем снимите осознанно |
| RPC-ошибки в логах | Ключ не задан (мок-режим выключен) | Заполните `ETH_RPC_HTTP` в `.env` или оставьте `MOCK_MARKET_DATA=true` |
| `sqlite3.OperationalError: unable to open database file` | Недоступен путь к БД | Проверьте права на `SQLITE_PATH` и volume `flashhunter_data` |
| Порты заняты | На хосте уже слушают :8000/:5432/:9090 | Измените `API_PORT`/`POSTGRES_PORT`/`PROMETHEUS_PORT` в `.env` |

Полезные команды диагностики:

```bash
docker compose logs -f --tail=200 api     # логи приложения
curl -s localhost:8000/api/v1/ping | jq     # лёгкая проверка живости
curl -s localhost:8000/api/v1/health | jq   # состояние (БД, оркестратор)
curl -s localhost:8000/metrics | grep flashhunter_kill_switch_active
docker compose exec api python -c "import flashhunter, sys; print(flashhunter.__version__, sys.version)"
```
